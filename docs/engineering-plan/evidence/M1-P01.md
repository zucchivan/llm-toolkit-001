## Step (b): capped no-follow host reads

### API and decisions

`src/util/safe-read.ts` exports:

- `SAFE_READ_LIMITS` — the §2 defaults (32 MiB/file, 512 MiB content, 100k
  entries, 4096-byte path, 255-byte component).
- `SafeReadBudget` — a shared admission counter. It may be constructed with a
  lower limit for a control bundle/test; construction above 512 MiB throws.
- `SafeReadResult<T>` — `{kind:"ok",value}` | `{kind:"absent",path}` |
  `{kind:"refused",code,path,message,bytesRead?}`. `absent` is only a genuine
  ENOENT on a non-symlink component; everything else is a refusal.
- `openSafeDirectory` / `openSafeFile` — pinned handles; callers must `close()`
  in `finally`. A pinned handle is what makes a later ancestor/leaf replacement
  unable to redirect the operation.
- `readSafeFile` / `readSafeText` — convenience one-shots.
- `listSafeDirectory` / `walkSafeFiles` — no-follow listings with the entry cap;
  the walk returns root-relative, sorted `files`/`directories` and refuses the
  whole walk on a symlink, FIFO/socket/device, unsafe name or count excess.
- `safeReadPrimitiveStatus(platform?)` — pure platform decision. The runtime
  additionally proves the proc-fd base exists and is a directory.

Path policy: the root must be a canonical absolute path (the caller resolves
the operator-selected root once); the requested path must be relative, NUL-free,
`/`-separated, free of `.`/`..`, control characters, drive/stream/UNC forms,
backslashes, Windows reserved device names and trailing dot/space components.
Directory entry names are held to the same component rules; a name Node decodes
to U+FFFD (invalid UTF-8 on disk) refuses instead of being rewritten.

Pinned handles are the deterministic proof for both swap cases: a directory
handle opened before an ancestor rename/symlink swap still resolves its child
from the original inode, and a leaf FD opened before a path replacement still
returns the original bytes. The tests do not rely on a timing race.

Primitive: on Linux each component is opened relative to a pinned directory FD
via `/proc/self/fd/<dirfd>/<child>`. `O_NOFOLLOW` rejects a symlink in the child
position; `O_DIRECTORY` rejects a non-directory ancestor; `O_NONBLOCK` on the
leaf makes FIFO open return immediately. On a non-Linux platform, or when the
proc-fd base is absent/not a directory, the result is a typed
`unsupported-platform` refusal. There is no `realpath`-then-open fallback, no
PATH search and no environment selector. `lstat` is used only to label a refusal
after the no-follow open already failed, never as the security boundary.

Caps: the per-file cap is checked against fstat before reading and again by the
read loop, which probes one byte past the cap so a file that grew after open is a
refusal rather than a truncated success. The shared content budget is checked
before and during the read; only a completed `ok` read is charged. Directory
entry counting stops at the cap and refuses; it never returns a truncated list.
`bytesRead` in a refusal is diagnostic only and is `0` when nothing was read.
