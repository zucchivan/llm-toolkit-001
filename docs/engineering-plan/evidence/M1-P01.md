### Approved decisions

1. **Validated fixed Linux defaults.** `process.execPath` for Node, the running
   operator-selected kit CLI/UI entry points, `/usr/bin/git` and `/usr/bin/gh`;
   explicit `installation.*` host-profile overrides; no PATH, cwd, project-env
   or `KIT_*` authority; **no fallback after an invalid selected path**.
2. **Resolve and validate on demand.** An unused tool is never resolved;
   `delivery.mode=none` must not require `gh`. No eager all-tool validation on
   the launch path.
3. **No-symlink installation trust.** Retain the no-symlink installation-path
   policy and validate the executable plus its ancestor directories. The only
   exception is the **running operator-selected dev-in-kit installation**
   (its own `dist/cli.js`, `ui/bin/llm-toolkit-ui.js` and `src/cli.ts`-via-tsx
   entries), proven by the running entry identity and never inferred from
   target cwd or the presence of a kit copy in the target.
4. **Host-owned descriptor injection.** Tests inject an explicit installation
   descriptor; injection is host authority, not a validation bypass and not a
   production-authority source. Job launch and attached-stop use one
   descriptor/argv identity; the runner revalidates and executes the recorded
   canonical argv without re-resolution.
5. **Async config reads.** `.orch/config.toml` is read through the canonical
   root + `safe-read` + the pure `parseConfig`; absent/refused/malformed stay
   distinct. A legacy sync config read is **not** packet completion.
6. **Git is more than an absolute path.** Preserve/enforce protection against
   Git-triggered host callbacks and hostile inherited configuration: fixed
   literal argv, host-built env with `GIT_*`/`GH_*`/`SSH_*`/proxy/`BASH_ENV`/
   `NODE_OPTIONS` stripped, and hooks/fsmonitor/external diff/textconv/aliases/
   filters disabled or avoided by plumbing. `gh` is noninteractive,
   destination-pinned and resolved only for `pr` + explicit `--deliver`.
7. **Unsupported platforms.** The operation needing a missing primitive/tool
   refuses explicitly; static commands with no project read or host launch do
   not acquire unnecessary Git/gh/UI/helper prerequisites.
8. **Boundary.** P01 prepares host boundaries only. Real gate/probe
   containment, probes, `[sandbox]` defaults and leases remain P05.

## Step (b): capped no-follow host reads

### API and decisions

`src/util/safe-read.ts` exports:

- `SAFE_READ_LIMITS` — the §2 defaults (32 MiB/file, 512 MiB content, 100k
  entries, 4096-byte path, 255-byte component).
- `SafeReadBudget` — a shared admission counter. It may be constructed with a
  lower limit for a control bundle/test; construction above 512 MiB throws.
- `SafeReadResult<T>` — `{kind:"ok",value}` | `{kind:"absent",path}` |
  `{kind:"refused",code,path,message,bytesRead?}`. `absent` is only a genuine
  ENOENT on a non-symlink component; everything else is a refusal.
- `openSafeDirectory` / `openSafeFile` — pinned handles; callers must `close()`
  in `finally`. A pinned handle is what makes a later ancestor/leaf replacement
  unable to redirect the operation.
- `readSafeFile` / `readSafeText` — convenience one-shots.
- `listSafeDirectory` / `walkSafeFiles` — no-follow listings with the entry cap;
  the walk returns root-relative, sorted `files`/`directories` and refuses the
  whole walk on a symlink, FIFO/socket/device, unsafe name or count excess.
- `safeReadPrimitiveStatus(platform?)` — pure platform decision. The runtime
  additionally proves the proc-fd base exists and is a directory.

Path policy: the root must be a canonical absolute path (the caller resolves
the operator-selected root once); the requested path must be relative, NUL-free,
`/`-separated, free of `.`/`..`, control characters, drive/stream/UNC forms,
backslashes, Windows reserved device names and trailing dot/space components.
Directory entry names are held to the same component rules; a name Node decodes
to U+FFFD (invalid UTF-8 on disk) refuses instead of being rewritten.

Pinned handles are the deterministic proof for both swap cases: a directory
handle opened before an ancestor rename/symlink swap still resolves its child
from the original inode, and a leaf FD opened before a path replacement still
returns the original bytes. The tests do not rely on a timing race.

Primitive: on Linux each component is opened relative to a pinned directory FD
via `/proc/self/fd/<dirfd>/<child>`. `O_NOFOLLOW` rejects a symlink in the child
position; `O_DIRECTORY` rejects a non-directory ancestor; `O_NONBLOCK` on the
leaf makes FIFO open return immediately. On a non-Linux platform, or when the
proc-fd base is absent/not a directory, the result is a typed
`unsupported-platform` refusal. There is no `realpath`-then-open fallback, no
PATH search and no environment selector. `lstat` is used only to label a refusal
after the no-follow open already failed, never as the security boundary.

Caps: the per-file cap is checked against fstat before reading and again by the
read loop, which probes one byte past the cap so a file that grew after open is a
refusal rather than a truncated success. The shared content budget is checked
before and during the read; only a completed `ok` read is charged. Directory
entry counting stops at the cap and refuses; it never returns a truncated list.
`bytesRead` in a refusal is diagnostic only and is `0` when nothing was read.

### What was built

1. Added the launch identity to the one host-owned resolver
   (`src/sandbox/trusted-exec.ts`): `selectLaunchPrefix(descriptor, "cli"|"ui")`
   is a pure selection returning `[node, entry]` for a JavaScript entry and the
   documented dev-in-kit `[node, <installation>/ui/node_modules/tsx/dist/cli.mjs,
   src/cli.ts]` form for the running installation's own TypeScript entry (a
   `.ts` path anywhere else refuses — no candidate search).
   `requireLaunchPrefix` validates the interpreter, the entry and (source form)
   the installation's own loader per use with the step (e) file-trust rules
   (the loader is installation-owned: it is validated with the dev-in-kit
   allowance, so symlink/owner/mode still apply).
   `installationDescriptorDigest` is a SHA-256 over the descriptor's selected
   tool paths — recorded identity, never authority. New typed refusal code:
   `unsupported-entry`.
2. `src/cli.ts` `cmdUi`: builds the descriptor (`loadTrustedInstallation`, host
   profile + fixed defaults) and starts the UI entry from the `ui` prefix with
   inherited stdio/env and the target cwd. `findUiBin` and its kit-repo
   `ui/node_modules/.bin`/target cwd/`ui/bin`/PATH search are **deleted**; an
   invalid/missing selected entry prints a typed refusal and exits 1 without
   trying another candidate.
3. `ui/server/cli.ts`: builds the descriptor ONCE at the UI entry and passes it
   to `startServer` (a malformed/unsafe host profile refuses the UI start with
   a plain reason; nothing is launched).
4. `ui/server/actions.ts` `resolveCli` is now async and descriptor-only
   (`requireLaunchPrefix(descriptor, "cli", {targetRoot})`). `KIT_UI_CLI_BIN`,
   the project `node_modules/.bin`, the kit `dist/cli.js` fallback, PATH and the
   target tsx chain are removed. `startAction` records the canonical identity
   via `spawnJob`; a refused entry answers 500 with `the trusted CLI entry is
   refused (<code>): <message>` and no job record.
5. `ui/server/jobs.ts`: `JobLaunchIdentity` + `jobLaunchIdentity` (built from
   the validated prefix and the descriptor digest), persisted in the private
   job record with the full argv. `jobEnvironment` is the ONE job-env policy:
   it keeps `KIT_FAUX`/`KIT_FAUX_SCRIPT`/`KIT_DEBUG*`, provider credentials,
   proxies and `PATH` for the CLI's own project work, and drops executable
   selectors (`KIT_UI_CLI_BIN`, undocumented `KIT_*`, `NODE_OPTIONS`,
   `NODE_PATH`, `LD_*`/`DYLD_*` loader variables, `BASH_ENV`/`ENV`).
6. `ui/server/job-runner.mjs`: before opening the log or spawning, revalidates
   the record against its own identity — identity version/tool, absolute
   `installationRoot` that MUST equal the runner's own installation root
   (proven from its module URL), `[node, ...(loader), entry]` equality with
   `argvPrefix` and with `record.argv`'s prefix, absolute cwd, and each
   recorded file still a regular non-symlink, operator/root-owned,
   non-group/world-writable file whose `realpath` is unchanged. A tampered,
   foreign or identity-less record is finalized as `failed` with a `refused:`
   detail and spawns nothing. The env is the server-sanitized inheritance plus
   `KIT_UI_JOB=1`; nothing in it can choose a different executable.
7. `ui/server/attached-stop.ts`: `/proc/<pid>/exe` must be the recorded node
   interpreter and `/proc/<pid>/cmdline` must contain the recorded prefix
   (`[node, ...(loader), entry]`, canonical token comparison against the
   verified cwd) followed by a `plan`/`run` subcommand. It no longer imports
   `resolveCli`; the check uses the same descriptor the UI entry passes down
   (or the process descriptor for direct callers). Check order, the Linux-only
   refusal and the never-signal-on-failure guarantee are unchanged.
8. `ui/server/server.ts` + `ui/server/sse.ts`: the descriptor flows from
   `startServer` to `/api/jobs`, the SSE `job` payload and the POST stop path

   {installation})`, `attachedStopAction(..., {installation})`).
9. Tests: `test/trusted-exec.test.ts` (+5) proves the pure/validated launch
