# Section 4 / M1 — split host authority from project execution

Read [IMPLEMENTATION.md](IMPLEMENTATION.md) first; its execution/evidence contract applies to every packet. This sheet assumes M0-P19 and the post-review M0 fixes are green. The local lane is required for production execution; unqualified optional tiers remain unavailable, not emulated. Use the path/env matrices in [§2](README.md), not backend defaults. Capability tests are required on every platform advertised as supported. A fake is useful to test a denial; it cannot certify a sandbox.

- **Specification:** Implement strict `HostProfile`, `LeaseSpec`, projection, env and safe-read policy as pure decisions; explicit backend and toolchain allowlist, no process fallback. Resolve canonical root once; reject missing/insecure host profile for operations needing its grants. Trust absolute installation-owned CLI/UI/git/gh/helper locations, not target `node_modules/.bin`, cwd-relative PATH, inherited Git aliases/hooks or arbitrary project executable; explicit trusted host override outside the target permitted. Dev-in-kit checkout is trusted only as the operator-selected installation, not by virtue of target cwd. Keep attached-stop matching the same resolved CLI entry. Validate host-controlled paths (`--prd`, config, recipes, remediations, artifact/source reads and `.orch` ancestry) before opening; never follow project symlinks to host files. Keep safe caps during reads, not just slices after full-file loads. Readonly observation must not take an execution lease. Put host policy under operator config, not project `.orch`; no raw secrets in a profile.
- **Internal steps (complete in order; not independent releases):** (a) map every host read/launch caller and validate the strict host-profile/installation schema; (b) implement capped no-follow reads and test leaf/ancestor/replacement/permission errors before wiring; (c) wire CLI/core/UI host reads and trusted binary resolution; (d) validate reviewed control identity and production call-site coverage, then review the packet. These are separate bounded sessions when necessary: stop after each step and hand off; do not attempt the whole path list in one edit. Engine paths beyond host read/launch wiring are authorized only for the control binding/reconciliation requirement below, not an engine refactor. `delivery.ts` owns PR publication in the M0 tree; do not create a second PR backend under the old planned filename. No sandbox launch or certification belongs to P01.
- **Additional binding requirements:** Validate actual configured/`--prd` path and reserve it read-only in projection/import, including when absent. Review identity must cover all `evals/**` regular-file bytes (including executable assertion scripts), PRD/PROMPT/remediations and effective verification/delivery/routing/sandbox settings, not only recipe TOML names. Capture once before disclosure; use those exact controls rather than hashing working files then executing different committed bytes. Validate at new grant, resume and each fresh retry boundary; a session-ceiling edit alone is not control drift. Reconciliation uses pinned identity/destination only and must stop before fresh work on drift. If the inherited snapshot/recovery architecture cannot support this within strict paths, record a blocker and request an amendment rather than claiming P01 complete.
- **Additional EARS:** When a symlink ancestor is swapped during a host read, no outside bytes shall reach a model/UI. When an eval helper or bound policy changes without replan, no new submission shall start. When reconciliation completes after control drift, no retry wave shall fall through under the old grant. Tests shall assert provider/tool/effect counts and unchanged refs, not just thrown errors.
- **Documentation & Template Updates:** Core `docs/project-contract.md`, `docs/api-map.md` and UI PRD/README/CHANGELOG document trusted binary resolution and path refusal. No shipped sandbox config default until P05. Preserve local stop verification, including refusal on unsupported OS.
- **Explicit Non-Goals:** No cross-OS signaling, global plugin registry or permissive backend if validation fails.
- **Acceptance Criteria (EARS format):** When a target names a binary inside its checkout, host launch shall not select it as orchestrator. When given an outside/symlinked PRD, config or artifact, the host shall return an error without reading its contents. When extra env/FD/network/paths are requested by a repo, policy shall deny them unless exactly authorized in §2. When a host lacks containment, static evidence reads shall still work. When applying the documented host profile to the policy fixture, no additional environment name or path shall become visible.
- **Verification Commands:** `npm run typecheck && npm test -- test/sandbox-policy.test.ts test/host-paths.test.ts test/reviewed-controls.test.ts test/m0-review-regressions.test.ts test/plan-revision.test.ts test/run-scope.test.ts test/interrupted-stage.test.ts test/resolve.test.ts`; `npm --prefix ui test -- test/actions.test.ts test/attached-stop.test.ts test/project-sources-server.test.ts test/diff-server.test.ts`.

- **ID & Title:** M1-P02: Put the complete file/exec interface behind a guest transport
- **Depends On:** [M1-P01]
- **Target Paths (Strict):** `src/engine/kit.ts`, `src/sandbox/{types,guest-env,guest-helper,protocol}.ts`, `test/{guest-env,kit-seam}.test.ts`, `docs/api-map.md`
- **Context Files to Read First:** `src/engine/{kit,conversations,harness}.ts`, `node_modules/@earendil-works/pi-durable/dist/env/index.d.ts:166–305`, `node_modules/@earendil-works/pi-durable/dist/tools/{read,edit,write,bash}.js`, `docs/api-map.md`.
- **Specification:** Use one versioned request/response stream per lease (`v:1,id,op,args` / `id,ok,value|code`, size-prefixed <=1 MiB frames, byte chunks <=64 KiB; response IDs must match one in-flight operation). Fixed op table, no dynamic module/method lookup. `GuestEnv implements ExecutionEnv`, path operations in guest coordinates, stable namespace id, namespace-local handles for binary/line/dir readers and cleanup. Run trusted helper and pinned `NodeExecutionEnv` **inside** guest; return typed `FileError/ExecutionError`, not host error stacks. Support all operations used by pinned read/edit/write/bash; unused watch/list optimizations may explicitly return `not_supported` per upstream contract; never silently route to host. Stdout/stderr separate and capped for recipe calls. String exec only for coding-tool bash; arrays exec directly without shell, including remote paths. Revoke handles/kill processes on close or cancellation; unauthorized handle/phase rejects. Use fixed guest resource paths, no host SDK/node_modules mounts except the deliberately provisioned read-only guest bundle. Tests can use paired in-memory transports; no production backend selector for fake.
- **Documentation & Template Updates:** `docs/api-map.md` list exact pinned env types/exports added via `kit.ts`, guest protocol, unsupported operations and cancellation semantics.
- **Explicit Non-Goals:** No custom agent tools, remote file editor, generic guest-to-host RPC or running the helper on the trusted host for production.
- **Acceptance Criteria (EARS format):** When exercising real registered file tools through the adapter, a read/edit/write sequence shall use guest paths and retain binary-reader handle identity. When sending literal argv with spaces, the helper shall preserve all argument boundaries. When a stale handle, unknown opcode, over-limit frame or unknown role is presented, the adapter shall fail closed. When a tool is canceled, no command shall remain owned by the canceled lease after fencing. When inspecting the API map, each exposed guest method shall have a tested transport operation or an explicit pinned-API unsupported result.
- **Verification Commands:** `npm run typecheck && npm test -- test/guest-env.test.ts test/kit-seam.test.ts`.

- **ID & Title:** M1-P03: Implement and certify the deny-by-default Linux local lease
- **Depends On:** [M1-P02]
- **Target Paths (Strict):** `src/sandbox/{local,lease-lifecycle,manifest}.ts`, `sandbox/local/{README.md,make-fixture-rootfs.sh}`, `test/{local-sandbox,sandbox-conformance}.test.ts`, `test/sandbox-fixture.ts`, `docs/{project-contract,api-map}.md`
- **Context Files to Read First:** `src/sandbox/{types,policy,guest-env,guest-helper}.ts`, `src/engine/workspace.ts`, `src/util/lockfile.ts:38–95`, §2 local matrix.
- **Required lifecycle proof:** Before implementation write the durable lease phase/observed cgroup/recovery-action table. Test crash after lease intent but before launch, after launch but before acknowledgement, after fence but before import, and after import but before result receipt. Reopen cannot trust a guest-supplied manifest/fence claim. Missing delegated cgroup capability blocks P03 and hence P04/P05; protocol mocks may be developed but cannot satisfy certification.
- **Specification:** Trusted absolute bwrap path; build argv from positive binds of verified rootfs + projected work and reserved RO controls, partial writable scratch per §2. Disable network, host IPC/PIDs and caps, stdio-only fixed helper; validate namespaces and denied resources **inside the launched namespace** before any project command, not just `--version`. Rootfs/prebuilt dependencies independent of host HOME; validate lockfile/toolchain manifest before use, no online fallback. Use a host-delegated cgroup-v2 child named by an already-journaled lease UUID. Place the trusted launcher inside it **before** it can execute project code. Guest cannot mount/write cgroupfs. On timeout/owner death/reopen use `cgroup.kill` then verify `cgroup.events: populated 0`; no PID-only fence and no launch without that capability. Separate helper control stream/identity from workload stdio and drop inherited descriptors. Record single-use lifecycle so reuse of an unrelated PID/group cannot certify the lease. Import sealed files only after descendants are dead; validate type/mode/path/size/digest with no symlink traversal, not arbitrary tar extraction. If local kernel/userns policy prevents launch, return `containment-unavailable` without spawning any project code. Build a reproducible minimal work fixture with the pinned Node runtime and no Git executable/credentials from trusted installed assets only; do not run a project script to provision it. Real test lane requires certified Linux host and explicitly prepared fixture. Ordinary `npm test` exercises offline policy fakes and reports real lane separately.
- **Documentation & Template Updates:** `sandbox/local/README.md`, `docs/project-contract.md`, `docs/api-map.md` specify prerequisites, immutable rootfs setup, offline dependencies, shared-kernel limits and diagnostics; mark not default until P05.
- **Explicit Non-Goals:** No Docker socket, `/` bind, transparent host dependency installation, new root dependency or certification by mock.
- **Acceptance Criteria (EARS format):** When a real Linux worker reads project source and runs an allowed tool, it shall succeed without seeing host credentials/state/network. When worker tries a protected write or gate tries to change candidate code, the OS shall deny it independent of hooks. When timeout or owner death occurs, lease processes shall be fenced before the manifest is imported. When required kernel primitives are missing, no project process shall run. When the local README's conformance command runs on an unqualified host, it shall report a capability failure rather than a certified pass.
- **Verification Commands:** `npm run build && npm test -- test/local-sandbox.test.ts`; on certification Linux: `bash sandbox/local/make-fixture-rootfs.sh && KIT_TEST_BACKEND=local npm test -- test/sandbox-conformance.test.ts` (required lane fails, does not skip, on missing capability).
