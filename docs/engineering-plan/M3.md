- **ID & Title:** M3-P01: Extract a read-only repo index and the in-tree JS detector
- **Depends On:** [M2-P09]
- **Target Paths (Strict):** `src/adoption/{types,discovery,repo-index,detectors/js,gaps,evaluate,evaluation-policy,workflow,cli}.ts`, `test/{detector-contract,adoption-discovery,adoption-gaps,adoption-workflow,adoption-evaluate}.test.ts`, `docs/{api-map,concepts,project-contract}.md`, `README.md`
- **Context Files to Read First:** `src/adoption/discovery.ts:40–119,150–175`, `src/adoption/gaps.ts:38–104,240–267,313–319`, `src/adoption/evaluation-policy.ts:44–96`, `src/adoption/workflow.ts:43–104`.
- **Boundary regression requirement:** Test absent versus unreadable/malformed/capped manifests independently; preserve unknown all the way through recommendations, refresh preview and remembered decisions. Discovery tests install spawn/import/write canaries and assert none fires, not merely that no recipe result is returned.
- **Specification:** Build one sorted slash-relative `RepoIndex` (no follow, no `.git`, `.orch`, vendor, `node_modules`, build/scratch; 100k paths, 256 KiB per text file, no executions/imports/shell). Mark unreadable/capped facts as unknown/warning rather than absent. Move JS manifest/CI conventions AND JS-specific coverage analysis behind the §3 `EcosystemDetector` interface. Registry is a fixed array in source; deterministic merge by finding ID, safe cwd + stable order. Generic layer owns recipe override, remembered decisions, fingerprint comparison/reopen, write preview/approval and separate execution consent. Keep existing JS IDs, serialized recipe semantics and fingerprint for unchanged evidence (golden fixtures); Expose JS package facts to the JS-only advisory shadow via `discoverJs(index)` in `detectors/js.ts`; neither `DetectorOutput` nor generic consent logic gets a JS package field. On incomplete enumeration, an unseen path is unknown, not absent. Do not run JS-specific global N/A rules if JS surface is absent. `safeRecipeCwd` already belongs to the shared runner from M0, not a language detector.
- **Documentation & Template Updates:** All listed docs: static discovery interface, where JS rules stop and generic policy starts, no executable plugins, existing decisions survive.
- **Explicit Non-Goals:** No second-language logic in this packet, command probing during discovery, new third-party parser, or changes to acceptance policy.
- **Acceptance Criteria (EARS format):** When baseline JS fixtures are analyzed, finding IDs, effective recipes and decisions shall remain stable. When an index entry is missing due to a cap/read fault, detector output shall say unknown/warn, not turn the gap into a generated command. When `gates list` runs, no process or adoption write shall occur. When two detectors return colliding IDs with distinct evidence, merge shall reject rather than discard one. When comparing the documented JS refresh example with the baseline golden fixture, the same evidence shall reopen the same decision IDs.
- **Verification Commands:** `npm run typecheck && npm test -- test/detector-contract.test.ts test/adoption-discovery.test.ts test/adoption-gaps.test.ts test/adoption-workflow.test.ts test/adoption-evaluate.test.ts`.

- **ID & Title:** M3-P02: Prove the detector contract on Go and mixed repos
- **Depends On:** [M3-P01]
- **Target Paths (Strict):** `src/adoption/{detectors/go,discovery,types,gaps}.ts`, `src/sandbox/policy.ts`, `test/{go-detector,mixed-adoption,adoption-cli,adoption-probe}.test.ts`, `test/data/mixed-adoption/{package.json,src/index.test.js,services/api/go.mod,services/api/main_test.go,services/api/nested/go.mod,services/api/nested/inner_test.go}`, `docs/{api-map,concepts,project-contract}.md`, `README.md`, `template/evals/recipes.toml`
- **Context Files to Read First:** `src/adoption/{repo-index,detectors/js,gaps,workflow,probe}.ts`, `src/sandbox/policy.ts`, `test/adoption-workflow.test.ts:28–77`, `src/adoption/gaps.ts:38–104`, §1 ADR 12.
- **Specification:** Find regular `go.mod` declaring a literal `module` directive. Attribute `*_test.go` to nearest module ancestor, never double-count nested modules/vendor. One unit-check finding per module `go:unit-test:<cwd>` (`.` for root). With an owned test, recommend `argv=["go","test","-mod=readonly","./..."]`, cwd at module, no match/on required. Recipe name `go-unit-<first12 sha256(cwd)>`; user override rules unchanged. Existing identical argv/cwd covers it; same human name with different command reports human override rather than guaranteed Go coverage. A manifest without tests gives missing + reviewable remediation, never an active green gate; an applicable `go.work`, nonliteral module directive, or local `replace` target not proven within this module → unknown, no guessed command. Do not evaluate Go code or resolve modules online to answer. Fingerprint includes normalized module path, manifest digest, contributing test paths and command/cwd; existing JS root gate doesn't cover Go by accident. Sandbox runs Go offline: guest constants `GOTOOLCHAIN=local`, `GOPROXY=off`, `GOSUMDB=off`, `GOCACHE=/tmp/go-build`, `GOMODCACHE=/opt/kit/go-mod-cache` RO preprovisioned. Missing tools/modules = diagnostic from *consented* probe, not discovery install.
- **Documentation & Template Updates:** Listed docs distinguish recognized Go facts, coverage limits and commands; add **commented** Go recipe in template (never default-on). Include mixed JS/Go refresh + probe example.
- **Explicit Non-Goals:** No Python/Rust, `go list`, executing helper scripts, recursive `go.work` evaluation, automatic installs or Go Jev classifier.
- **Acceptance Criteria (EARS format):** When JS and nested Go modules coexist, both sets of findings shall appear with distinct IDs/cwds. When a deferred Go module's evidence changes, only affected decisions shall reopen. When a noninteractive refresh lacks explicit acceptance or probe lacks consent, no recipe write or command execution respectively shall occur. When a written Go recipe is probed, it shall use the same sandboxed literal runner with no network or adoption-state mutation. When parsing the shipped default recipe template, the documented Go example shall still be a comment, not an active check.
- **Verification Commands:** `npm run typecheck && npm test -- test/go-detector.test.ts test/mixed-adoption.test.ts test/adoption-cli.test.ts test/adoption-probe.test.ts`.

- **ID & Title:** M3-P03: Specify and test the bounded greenfield interview as a pure state machine
- **Depends On:** [M3-P02]
- **Target Paths (Strict):** `src/greenfield/intake.ts`, `test/greenfield-intake.test.ts`, `docs/project-contract.md`
- **Context Files to Read First:** `src/init.ts:17–65`, `src/adoption/cli.ts:89–101`, `src/adoption/workflow.ts:109–170`, `src/config.ts`, §3 config and M0 base requirement.
- **Specification:** Fixed order: `name` (kebab slug, 1–48), `scope` (one objective, 10–500 chars), `stack` (literal `node-cli`, unsupported stack exits with no scaffold), `nonGoals` (1–5 nonempty strings <=160 chars), `acceptance` (1–5 explicit `When …, the system shall …` examples <=240 chars; confirms verification strategy = behavioral Node smoke + these future PRD criteria), `sessionUsd` (finite [0,1000], incl. 0), `delivery` (`none|commit|pr`; show extra PR consent/destination requirement). Reject placeholders such as blank/TBD; never invent a missing answer. Max 2 retries per invalid field then abort; EOF/cancel abort. Final review lists exact paths, values, smoke command, seed-commit effect and what is not done; only literal `yes` continues. Noninteractive JSON object requires exactly those seven keys/validation; require separate `--yes`. This is a **new-directory-only** scaffold; the reviewed one-time local seed commit is necessary to give the loop a valid base. Pure transitions return data/intents, no file or model access.
- **Documentation & Template Updates:** Add bounded intake and consent contract to `docs/project-contract.md`, clearly marked not yet exposed until P04.
- **Explicit Non-Goals:** No AI interview, multiple stack selection, “clarify until forever,” global user identity lookup or arbitrary template execution.
- **Acceptance Criteria (EARS format):** When inputs are incomplete, ambiguous or unsupported, the interview shall re-prompt only that field or terminate at the cap without writes. When all fields validate, review shall include objective, non-goals, concrete behavior, budget, mode and seed-commit effect. When confirmation is declined/EOF or noninteractive `--yes` is absent, no scaffold intent shall be produced. When all seven answers are supplied identically in JSON and TTY form, normalized scaffold intents shall agree. When comparing the contract's seven-field table to the validated intent, prompts, bounds and abort conditions shall match.
- **Verification Commands:** `npm test -- test/greenfield-intake.test.ts`; `npm run typecheck`.

- **ID & Title:** M3-P04: Generate one loop-ready CLI scaffold and prove the smoke can fail
- **Depends On:** [M3-P03]
- **Target Paths (Strict):** `src/{init,cli}.ts`, `src/adoption/cli.ts`, `src/greenfield/{intake,scaffold}.ts`, `template/greenfield/{package.json,bin/main.mjs,evals/smoke.mjs,evals/recipes.toml}`, `test/{greenfield-cli,greenfield-smoke}.test.ts`, `README.md`, `docs/{concepts,project-contract,api-map}.md`, `CHANGELOG.md`
- **Context Files to Read First:** `src/cli.ts:88–108,529–553`, `src/init.ts:27–100`, `template/{PROMPT.md,.orch/config.toml,evals/recipes.toml}`, `src/greenfield/intake.ts`, `src/hygiene.ts`, `test/e2e.smoke.test.ts`.
- **Required failure table:** Cover cancellation before reservation, exclusive-reservation conflict, partial write, commit failure and crash after commit before completion marker. Verify actual named commit entries and HEAD before declaring loop-ready; retry must not create a second seed commit or adopt an unrelated directory. An incomplete root stays blocked with a manual remedy, never auto-deleted or silently treated as a normal project. Keep this separate from future PRD acceptance; the smoke proves only the scaffold contract.
- **Specification:** `init <new-dir> --greenfield [--answers <json> --yes]`; reject combination with `--with-demo`, existing dir (even empty), destination inside another worktree, non-TTY without reviewed inputs, symlink parents, files outside root. Read <=16 KiB answer JSON as data. After consent reserve new dir exclusively, mark incomplete until all writes and seed commit verify. On failure report path/remedy, don't delete a pre-existing path; other CLI mutations refuse incomplete root. Render normalized data into docs/PRD and JSON/TOML as *data*, never interpolate it into executable code/commands. Emit `docs/prd.md`, `PROMPT.md`, `.orch/config.toml` v2 with specified ceiling/mode, `evals/{checklist.md,recipes.toml,smoke.mjs}`, `router.md`, `.gitignore`, `package.json` (`type:module`, version `0.1.0`, no deps), `bin/main.mjs`. `node bin/main.mjs --version` prints `0.1.0\n`, exit 0; invalid args print usage on stderr, exit 2. Smoke script spawns that actual CLI and asserts both cases. Recipe `argv=["node","evals/smoke.mjs"]`. Initialize Git with controlled options/hooks disabled, **only** named reviewable scaffold files in a seed commit with fixed local kit identity; verify HEAD, do not touch global config. No installs, model call, probe or auto-run. Print separate `gates probe --yes` and plan/review steps. Preserve ordinary `init` brownfield behavior.
- **Documentation & Template Updates:** Exact scaffold templates listed; docs/CLI help describe the supported stack, consented local seed commit, future-vs-scaffold criteria, refusal to overwrite, and dependency-free verification commands.
- **Explicit Non-Goals:** No implementation of the user's proposed product, remote provisioning, creating a repo in an existing checkout, implicit PR/plan/verify or invoking the smoke during intake.
- **Acceptance Criteria (EARS format):** When given valid approved answers, scaffold shall parse via the actual config/recipe loaders and contain one scoped seed commit. When separately probed in a certified sandbox, its behavioral smoke shall pass; when the version output is deliberately changed in a disposable new base commit, the same probe shall fail. When input contains quotes/metacharacters, they shall remain data and cause no extra command. When canceled or targeting an existing project, it shall leave that project unchanged. When following the documented init transcript, the seed commit shall contain only the listed reviewable files; no probe, approval or remote operation shall be recorded.
- **Verification Commands:** `npm run build && npm test -- test/greenfield-intake.test.ts test/greenfield-cli.test.ts test/greenfield-smoke.test.ts`; certified Linux: `KIT_TEST_BACKEND=local npm test -- test/greenfield-smoke.test.ts`; `node dist/cli.js --help`.
